# SEOの生成と確認

Python 3.11以降と、画像処理用Pillow 13.0.0を使います。Netlifyではrequirements.txtからPillowを導入し、Python 3.13で実行します。生成時の外部通信・API・CMS自動保存はありません。

ローカルでは `python -m venv .venv`、`.venv\Scripts\python -m pip install -r requirements.txt` で専用環境を用意します。以下のpythonコマンドは、この仮想環境のPythonで実行してください。

## 通常の作業

1. CMSは従来どおり `public/content/site.json` を更新します。
2. `python -B scripts/build_seo.py` を実行します。
3. `python -B scripts/preview_seo.py` を実行し、表示されたlocalhostのURLで確認します。

`public` は入力専用、`_site` は公開用の生成先です。生成物を直接編集せず、データやテンプレートを直して再生成してください。
以前からの `public` のプレビューも使用できますが、SEO設定と正式記事URLは `_site` 側で確認してください。

## 公開用URLと設定

- 旅の記事：`/journeys/記事ID/`
- 制作記事：`/making/記事ID/`
- 旧 `/journey/?slug=...`、`/making-article/?slug=...` は新URLへ301転送します。
- 正式URLは環境変数 `SITE_URL`、未指定ならCMS設定の `site_url` を参照します。独自ドメインへ変更する際は `SITE_URL` を設定し直して再生成します。
- 各記事の初期HTMLにタイトル、説明文、見出し、本文、画像、canonical、OGP、Twitter Card、Article構造化データを出力します。
- トップ・一覧にも初期HTMLの記事リンクを出力し、JavaScript未実行でも全記事へ到達できるようにします。
- sitemap.xml、robots.txt、404.html、旧URLの転送設定を自動生成します。管理画面と旧共通テンプレートはnoindexです。
- Netlifyは `python3 -B scripts/build_seo.py && python3 -B scripts/test_seo.py SEOTests NavigationLogicTests` を実行し、生成物と回遊ルールの検証に合格した場合だけ `_site` を公開する設定です。今回のローカルビルドだけでは公開しません。

初期本文は安全な許可リスト付きの簡易Markdown表示です。見出し・段落・強調・画像・リンク・リスト・表・既存HTMLの主要要素に対応します。ブラウザでは従来どおりmarkedが本文を表示し直します。複雑なMarkdown拡張機能は初期HTMLと差が出る可能性があります。新しい記法を使う場合はJavaScript無効時も確認してください。

公開用コピーのJSは新URLへ対応し、制作情報を二重に追加しないように調整します。CMS設定・入力方法は変更しません。確認できた写真の空のaltのみ、記事データに補っています。
削除記事の古い生成HTMLと、元から削除されたコピー済みファイルを生成記録に基づいて除去します。public内に残る旧記事HTMLも、CMSに該当記事がなければ公開用コピーから除きます。削除記事への固定フッターリンクは文字を残して無効化します。初回に既存の `_site` がある場合は上書きを停止します。

## CMS保存から公開用HTMLまで

公開後のGitHubバックエンドでは、CMS保存がリポジトリのmainブランチに反映され、NetlifyのGit連携が有効ならビルドを起動します。ビルドはpublic/content/site.jsonを読み取り、_siteを生成・検証します。テスト失敗時は公開を停止します。Git連携や自動ビルドの設定はNetlify側でも確認が必要です。

ローカルCMS保存だけではPythonは自動起動しません。ローカルでは保存後に生成・検証コマンドを手動実行します。公開先を_siteへ変更しても、CMSのGit保存先は従来のpublic/content/site.jsonのままです。

`python -B scripts/test_seo.py` は生成物・SEO・画像・回遊性の検証に加え、隔離コピーで追加・更新・削除・再生成・入力検証を試験します。実際のpublicは編集しません。実CMSのログイン・保存UIやNetlifyのデプロイは実行しません。検証コピーの保存先は環境変数SEO_TEST_WORKで指定でき、未指定時はOSの一時フォルダになります。

## 公開前後に行う確認

- `python -B scripts/test_seo.py` で生成結果と安全性を確認。
- PC・スマートフォンで記事を確認。入力写真のalt不足や容量は別の改善項目です。
- 公開後にGoogle Search Consoleで所有権確認、サイトマップ送信、URL検査を行う（今回自動実行しません）。DNS認証情報や確認用トークンは、必要時に所有者が用意します。
- Netlifyの実際の301・404応答とSNSの共有プレビューは公開後にも確認が必要です。余分なクエリ付き旧URLは転送ルールに一致しない場合があります。

## 画像の自動最適化

- 使用されるJPEG・PNG・WebPから、横幅640/960/1600/2000px以下の派生画像を生成します。拡大・トリミングはしません。SVGはそのまま使用します。
- JPEGとWebP（透過画像はPNGと可逆WebP）を比較し、品質基準を満たす小さい形式を採用します。元画像はpublicに保持します。_siteには参照が残る元画像だけを公開し、未使用OGP画像も生成・公開しません。
- 派生画像は_site/assets/optimized/へ出力。HTMLと公開用JSONの参照だけを切り替え、元画像・CMS保存先・本文の文章は維持します。
- srcset/sizes、縦横サイズ、優先読み込み・遅延読み込みを設定します。CMSのJSが作り直した画像にもresponsive-images.jsで同じ設定を適用します。
- OGPとArticleの画像は、絶対URLのJPEG/PNGを出力します。
- .image-cacheに内容ハッシュと変換設定で保存し、同じ画像は再変換しません。Netlifyでは同梱の小さなローカルプラグインが組み込みキャッシュAPIで復元・保存します。追加のnpmパッケージはありません。
- 初回は全画像を変換するため時間がかかります。記事追加時は新規・変更画像だけ処理します。キャッシュを失っても元画像から再生成できます。
- 将来の写真の内容は自動推測しません。CMSのALT欄とMarkdownの画像説明に入力した情報を優先します。装飾用の空altも保持します。
- 容量・形式・品質の実測は_site/assets/image-report.jsonとimage-manifest.jsonに出力します。画面別の全候補を同時ダウンロードするわけではありません。

## 記事を探す・次の記事へ移動する導線

- 既存のジャンル別新着欄を維持し、その前に旅・制作を合わせた新着3件をコンパクトに表示します。公開日が新しい順で、同日は元の登録順を維持します。タイトル等の更新は次回ビルドで反映されますが、公開日は自動変更しません。
- 各一覧に、記事が存在する既存カテゴリーだけを件数付きで表示します。カテゴリー別ページも静的HTMLで生成するため、JavaScript無効でも利用できます。
- URLは `/journeys/category/day-solo/`、`/making/category/3d-printing/` など。CMSの分類名・入力項目は変更しません。将来分類が追加されても、分類名から安定した識別子を作成します。
- 記事末尾に同ジャンルの関連記事を最大3件表示します。自分自身は除外し、旅は地域・ライドカテゴリー、制作は制作カテゴリーを優先した後、新しい記事から補います。他の記事がなければ関連記事欄を表示しません。
- 「前の記事」は同ジャンルの古い記事、「次の記事」は新しい記事です。一覧へのリンクとパンくずをまとめ、既存の制作記事の戻るリンクは置き換えて重複を避けます。
- パンくずのBreadcrumbListをArticle構造化データに追加し、カテゴリー別ページもcanonical・OGP・サイトマップへ反映します。
- 削除された記事と、記事が0件になったカテゴリーへの導線は、生成記録に基づいて次回ビルドで除去します。
- 確認は `_site` 用のローカルプレビューで行います。ソースのpublicだけを直接配信すると、新しい回遊導線はまだ生成されていない状態です。

## GA4とアクセス解析の同意管理

Google発行のGA4測定IDはGit管理外の.env.ga4.localに保存しました。GA4_ENABLEDはfalseで、本番計測は有効にしていません。通常ビルドでは計測コードは出力しません。同意画面と設定ボタンは計測が有効な本番の公開ページだけに表示します。ローカル・プレビューやGA4無効時には表示しません。

### 起動条件

- 測定IDはGoogle発行の値をGA4_MEASUREMENT_IDに一元設定します。GA4_ENABLED=trueかつNetlifyのCONTEXT=productionのときだけ、サイトマップ内の全公開ページへGA4コードを挿入します。
- 本番URLと一致するHTTPS origin、かつ有効な同意がある場合だけGoogleスクリプトを読み込みます。管理画面・旧共通テンプレート・404にGA4は挿入しません。
- 同意画面とフッターの設定ボタンは、GA4が有効な本番のサイトマップ対象ページで、フッターのあるページに生成します。JavaScript無効時は設定ボタンも非表示になり、GA4は起動しません。
- Google Signalsと広告パーソナライズは無効です。広告・User-ID・フォーム内容の送信は追加しません。page_location/page_referrerからクエリとフラグメントを除きます。

### 同意の保存と撤回

- 初回は同意する・同意しないを同じ大きさ・配色で表示します。モーダルではなく、拒否や未選択でも本文を閲覧できます。
- localStorageのride-and-make.analytics-consentに、choice、time（選択時刻）、versionだけを保存します。外部へ同意記録を送りません。現在の方針バージョンは1です。
- 保存済みの有効な選択があれば再表示せず、フッターの「アクセス解析の設定」から変更できます。保存できない場合、旧形式・不正値の場合は計測しません。
- 方針を変更するときはanalytics-consent.jsのVERSIONも更新し、再同意を求めます。記録はブラウザ内だけであり、サーバー保存や認定CMPではありません。
- 撤回・別タブでの拒否・選択削除時には、Googleのga-disableフラグで以降の送信を止め、アクセスできる_ga等のCookieをホスト・親ドメイン・パスについて削除します。第三者ドメインやHttpOnlyのCookieは削除できません。
- GA4が起動済みなら、撤回時にページを再読み込みして既存の処理を終了させます。既に送信したデータや通信中の送信は遡って取り消せません。
- 同意済みでもビルド設定が未設定・ローカル・プレビューならGA4は読み込みません。GA4の同意はYouTube・Strava・Tallyの動作を制御しません。

## 画像の位置情報対策（公開前の必須確認）

JPEG・PNG・WebPは画素を再エンコードせず、EXIF GPS、位置情報を含むXMP、IPTCの場所情報を除去します。EXIFの撮影日時・機材・向き・ICCは維持します。メーカー独自MakerNote、位置情報のあるXMPパケット全体、PNGのテキストメタデータは不明な位置情報を残さないため除去します。非位置情報の一部も同時に削除される場合があります。通常のCMS入力項目は変わりません。

CMSはブラウザ標準の画像ファイル選択・ドロップ・画像貼り付けを保存前に処理します。Decap 3.18.0には公式の画像保存前イベントがないため、CMS内部関数は上書きせず、documentのファイルイベントを捕捉して安全なFileだけを渡しています。処理失敗・非対応形式では元ファイルを渡さず、画面にエラーを表示します。ローカル／GitHubバックエンド共通です。CMS更新時はアップロード操作の回帰試験が必要です。

- JPEG・PNG・WebP：自動除去対応。画像の解像度・向き・名前を維持し、JPEG圧縮データ、PNG画素データ、WebP画素データを再圧縮しません。
- SVG：メタデータのない既存SVGを検査のみ通します。位置情報やmetadata要素のあるSVGは自動修正せず拒否。
- HEIC／HEIF／AVIF／TIFF／GIF／BMP／JXL、未知のメタデータ構造・破損ファイル：自動除去非対応。保存・ビルドを停止するので、位置情報を除いたJPEG・PNG・WebPを用意してください。
- 外部画像URLの直接入力：手元の画像ファイルがないので自動除去・外部画像の検査はできません。利用許可と位置情報はリンク先の管理者に依存します。
- 記事作成ヘルパーは画像を変換・サイト保存せず、候補パスを出力する独立ツールです。ヘルパー自体は今回変更しません。最終的にCMSからアップロードすれば自動処理が適用されます。
- 手動コピー・GitHubのWebアップロード・プログラムからの直接登録はCMSイベントを通りません。手元でバックアップし、下記の除去・検査後にGitへ選別登録してください。GitHub上の直接登録はビルド前にリポジトリへ送信されるため避けてください。

ビルドは元のpublic画像と最適化後の_site画像を検査し、除去対象・非対応画像があれば公開を停止します。ビルド自身は元画像を書き換えません。キャッシュは引き続き内容ハッシュを使い、変更画像だけを再変換します。

```text
python -B scripts/check_image_privacy.py
python -B scripts/check_image_privacy.py --clean "対象画像のパス"
python -B scripts/check_image_privacy.py --staged
python -B scripts/check_image_privacy.py --pre-push
```

--cleanは明示したファイルだけを書き換えるため、必ず先にプロジェクト外へバックアップしてください。--stagedは作業ツリーではなくGitインデックスの画像を検査します。--pre-pushはさらにupstream未送信の過去コミットも検査します。送信直前にはリモート状態を確認し、--pre-pushを実行してください。座標は表示しません。Gitフックは自動設定していないので、このコマンドを省略したpushやCMS以外の直接登録を自動的に阻止するものではありません。

任意の文章や画像に写った地図・場所、独自の不明なメタデータまで匿名化する機能ではありません。GPSのある元画像を以前コミットしている場合、現在の画像を修正しても履歴は残ります。履歴変更は別途の承認とバックアップが必要です。
